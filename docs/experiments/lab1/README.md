# Эксперимент Lab 1

5 октября 2026 в режиме учёбы проверена модель `qwen/qwen3.8-27b:free`. Эксперимент состоял из двух частей: сравнения коэффициента креативности ответа (temperature) и сравнения краткой и уточнённой инструкций.

## Сравнение temperature

Для всех прогонов использовался один и тот же запрос: объяснить разницу между интерфейсом и абстрактным классом в C#, привести бытовую аналогию, два примера кода и три рекомендации по выбору. Запрос и полный системный промпт сохранены в [протоколе](temperature-protocol.json).

Проверялись значения `0.0`, `0.3`, `0.7` и `1.0`; на каждое приходилось по три отдельных запуска. Перед каждым бот устанавливал выбранное значение командой `/settings`, сбрасывал историю через `/reset` и отправлял тот же запрос. Остальные параметры, включая модель, режим, промпт и лимит ответа, оставались постоянными. Все 12 ответов, длина, статистика токенов и оценки находятся в [результатах](temperature-results.json).

### Список экспериментальных прогонов

Во всех температурных прогонах задавался один вопрос о различиях интерфейса и абстрактного класса в C#.

| Прогоны | Temperature | Что проверялось |
| --- | ---: | --- |
| 1, 5, 9 | 0.0 | Повторяемость, корректность и полнота ответа при минимальной вариативности |
| 2, 6, 10 | 0.3 | Те же признаки при низком коэффициенте креативности |
| 3, 7, 11 | 0.7 | Те же признаки при среднем коэффициенте креативности |
| 4, 8, 12 | 1.0 | Те же признаки при максимальном коэффициенте в эксперименте |

В каждом ответе проверялись понятность объяснения, бытовая аналогия, два отдельных блока `csharp`, три рекомендации, текстовый формат, длина и доступная статистика токенов.

| Прогон | Инструкция | Что проверялось |
| --- | --- | --- |
| 1 | Краткая: «Объясни интерфейс и абстрактный класс в C#» | Ответ модели при минимальных указаниях в пользовательском запросе |
| 2 | Улучшенная по R.C.T.F. | Изменения полноты, примеров и соблюдения формата после уточнения роли, контекста, задачи и формата |

Предварительный запрос к API проверял только доступность модели и в результаты эксперимента не включался.

| Temperature | Средняя длина | Средняя оценка из 10 |
| --- | ---: | ---: |
| 0.0 | 2378 символов | 8.00 |
| 0.3 | 2244 символа | 8.33 |
| 0.7 | 2163 символа | 6.67 |
| 1.0 | 2852 символа | 8.00 |

Каждый ответ оценивался вручную по пяти критериям, каждый от **0 до 2 баллов**:

- корректность объяснения;
- ясность;
- бытовая аналогия;
- примеры кода;
- практические рекомендации.

Баллы по пяти критериям складываются: максимальная оценка ответа — **10 баллов**.
Средняя оценка в таблице — среднее арифметическое оценок трёх ответов
для каждой температуры. Например, при `0.3`: `(8 + 9 + 8) / 3 = 8.33`.
Это ручная оценка качества, а не результат автоматических тестов;
длина ответа рассчитывается отдельно и напрямую на баллы не влияет.

При `0.3` результат оказался немного лучше и короче. При `1.0` ответы в среднем были заметно длиннее. Длина не менялась линейно с temperature. Все ответы содержали два отдельных блока `csharp`, однако в одном примере при `0.7` пропущен `override`, поэтому он не компилируется. Также в ответах встречалось упрощение, будто интерфейс C# вообще не может содержать реализацию; в современном C# возможны реализации методов по умолчанию.

## Сравнение инструкций

Для второй части при temperature `0.3` отправлены два разных пользовательских запроса по одному разу: короткая неполная инструкция и улучшенная по R.C.T.F. (роль, контекст, задача, формат). Между ними история также сбрасывалась. Короткий запрос дал один общий блок кода и не включил аналогию и три явные рекомендации. Улучшенный дал два отдельных блока, аналогию и три рекомендации. Полные тексты и ответы сохранены в [результатах сравнения](instruction-results.json), условия — в [протоколе](instruction-protocol.json).

## Общий вывод

Для этого запроса `0.3` выглядит наиболее удачным рабочим значением: при небольшой выборке оно получило лучшую среднюю ручную оценку без чрезмерно длинных ответов. Уточнение роли, аудитории и формата заметно улучшило полноту ответа. Вывод предварительный: temperature проверялась всего на одном запросе с тремя повторами на значение, оценки качества субъективны, а генерация модели остаётся вариативной.
